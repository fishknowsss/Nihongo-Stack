# Nihongo Stack · Codex v0.6.0

本机优先的 Mac 日语学习应用，可双击 `Nihongo Stack Codex.app` 使用，无需终端或本地服务器。暖白 Solid Glass 分层与统一控件、朱红主动作、清晰的中文操作层级与明朝体日文阅读排版；应用图标为米白朱红叠放书页。

## 开始学习

1. 首次使用可做六题起点小测，不会时选“不知道”。小测只定位基础缺口，不代表 JLPT 水平。
2. 在「课程」选择基础单元；「今日」依次安排到期卡、单元新卡、配套阅读与听音。
3. 先回忆卡片，再查看答案并反馈。阅读/听音提交后显示解析；重新打开仍可查看结果，点击「重新练习」才开始新作答。
4. 时间有限时可跳过或延期。跳过原因、近七天反馈和作答保存在「进度」，用于真实使用后调整计划。
5. 在「卡片库」按日文、读音、中文或单元检索，筛选到期、新卡、最近困难与收藏。展开释义和收藏不会改动排程。列表每批显示 20 张，可继续加载；筛选检索会回到首批。
6. 复习每轮默认最多 10 张，可在设置中选 5 / 10 / 20 / 30 张；空格揭晓，1–4 反馈。轮次结束后可以休息或继续。
7. 设置默认每日时间；「今日」调整的时间只影响当日。任务估时超出可用时间时会提示。
8. 在「进度」回看错题；只依据每份材料最新一次实际作答，阅读辅助、合成语音与真人首遍/重练分别标明。重新答对后移出。
9. 学习页提供前台活跃计时，可手动暂停或结束；后台、失焦与闲置 60 秒后的时间不计入。「进度」显示最近七天保存的活跃时间。计时是本机记录，不上传。
10. 在「今日」或「课程」展开「本单元学习要点」，集中查看六个词句、例句、阅读重点和复盘提示。
11. 在「进度」查看「一周学习回顾」：截至昨天的七天活跃时间、学习类型、每日反馈与提交，以及任务调整原因。今日时间单列，学习安排仍由你手动调整。
12. 阅读的「阅读注音」可选关闭、材料注音、字体注音；FuriFont Serif 随应用离线提供，原材料读音优先。学习要点、卡片例句与展开后的听音文本也提供字体注音。自动读音结合上下文核对。
13. 理解题显示已答数量，可跳到首道未答题；窄窗口可在原文和理解题之间直接跳转。
14. 在「设置」定期导出 JSON。恢复先显示双方记录数量，勾选已核对后才可确认；导入前副本会保留在本机，可另行导出。
15. 阅读、听音文本和卡片例句可切换学习层：只看原文、汉字平假名、片假名简释、罗马音或全部层。排版固定为罗马音在上、平假名在汉字上方、释义/语法在原文下方。
16. 在任意日文材料中选中文字，会打开读音、释义和语法说明；可收藏并写笔记。笔记、收藏和 JLPT 练习进度都进入本机备份。
17. 「JLPT」按 N5–N2 与 2019–2025 建立学习索引；索引里的 6 题包是原创教学入口，不标作历年真题。官方 2012、2018 样题/练习册与题型说明提供直达入口。
18. 取得有权使用的完整真题后，按 `apps/codex/src/jlpt-import.ts` 中的 schema 导出为 JSON，点击「导入完整真题 JSON」即可在本机按年份、场次、等级、科目和听力音频练习；导入内容随本机备份保存，不自动上传 GitHub。

## 内容范围

总计 **62 张卡、9 篇短文、10 段音频、7 个基础单元**；JLPT 教学包另行维护，目前包含 24 道分级教学题和 28 个年份/等级学习索引。完整历年试卷通过本机授权导入，不把未经许可的考试原文、音频或 PDF 提交到公开仓库。

- 原 v1：20 张卡、2 篇短文、3 段 Tatoeba 真人短句。ID、文字与题意保持原样。
- 新 v2：介绍自己 → 一天的时间 → 地点与交通 → 购物与数量 → 邀约与安排 → 天气与条件 → 综合复盘。
- 每单元新增六张卡、三道阅读题、两道听音题、译文、解释和复盘提示。预计 25～35 分钟，只作参考，可分多天完成。
- 新增七段音频是 **macOS Kyoko 合成语音**，用于私人基础练习，不计入真人首遍听力表现。
- 原创内容已做结构、题文对应和基础语言检查，**未经过专业日语教师审校**。七单元为连续试用材料，不是正式教材、N2 课程或分数测评。

### 完整 JLPT 题库导入

完整试卷 JSON 的根对象保留 `schemaVersion: 1`、`id`、`year`、`session`、`level`、`title`、`sourceName`、`license`、`complete` 和 `questions`。每道题至少需要 `id`、`section`、`prompt`、`options`、`answer`；可补充 `reading`、`gloss`、`explanation`、`studySteps`、`itemType`、`audioUrl` 和 `sourceUrl`。

只有在确认整套试卷确实完整时才填写 `complete: true`，并同时提供：

- `session`：考试场次，例如 `07` 或 `12`；
- `questionCount`：必须等于 `questions.length`；
- `sectionQuestionCounts`：`文字・語彙`、`文法`、`読解`、`聴解` 四科的题数，四科实际题数和声明必须完全一致；
- 每一道 `聴解` 题的 `audioUrl`。

导入器会拒绝缺科目、题数不符或听力缺音频的“完整题库”标记。可以先运行 `npm run validate:jlpt -- path/to/pack.json`，再在应用内导入。`complete: false` 适合教材节选、单科练习或只有部分题目的学习包。

阅读、听音与小测草稿自动保存。听音按实际连续播放覆盖判断是否完整；拖到末尾不能绕过提交门槛。重播、拖动、变速或提前查看文本会作为辅助记录。提交后查看文本和播放不会修改已保存的证据。

## 数据与使用边界

- 保持 `com.nihongostack.codex` 和 IndexedDB `nihongo-stack-codex`，旧数据可继续使用；兼容原 v1 JSON 备份。
- 桌面应用、Mac 浏览器与 iPhone 浏览器的数据彼此独立；没有自动同步或公开网站。
- 学习卡片的“进入复习”、课程的“已练”都是记录口径，不能当作掌握判定。
- 导入前副本是本机防误操作措施，不代替外部文件备份。下一次恢复会更新这份副本。
- 应用采用本机临时签名，未 Apple 公证。合成语音再分发权限未核验；公开分发前须逐项复核内容和媒体许可。

## 开发与验证

在 `apps/codex/` 运行：

```sh
npm ci
npm run test:db
npm run test:learning
npm run test:content
npm run test:jlpt
npm run build
npm run tauri:build
codesign --verify --deep --strict 'Nihongo Stack Codex.app'
```

`test:content` 核对 v1 内容指纹、ID、引用、题目及十段音频的解码；它不是教师审校或听感审听。`test:learning` 检查播放覆盖、跳播缺口、暂停恢复、辅助证据与复习队列。`test:db` 使用内存 IndexedDB，不改真实记录。

原生恢复的写入验收使用 `qa` Rust feature 与独立 WKWebView data store，不使用正式学习数据。QA 构建配置与当轮证据见 `../../output/product-improvement/2026-10-07/`。v0.3.0 的独立 QA 配置、导出文件与验收见 `../../output/product-improvement/2026-10-08/`。正常使用只启动本目录的 Codex 应用，不启动 QA 应用。

窗口框架固定，只有正文滚动；短窗口侧栏可单独滚动。v0.4.0 独立 QA 与滚动证据见 `../../output/product-improvement/2026-10-08-v04/`。
