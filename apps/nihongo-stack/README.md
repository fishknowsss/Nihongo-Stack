# Nihongo Stack v0.7.0 · MyGo

本机优先的 Mac 日语学习应用，可双击 `Nihongo Stack.app` 使用，无需终端或本地服务器。桌面壳使用 MyGo，浏览器前端仍可独立构建。暖白 Solid Glass 分层与统一控件、朱红主动作、清晰的中文操作层级与明朝体日文阅读排版；应用图标为米白朱红叠放书页。

## 开始学习

1. 首次使用可做六题起点小测，不会时选“不知道”。小测只定位基础缺口，不代表 JLPT 水平。
2. 在「课程」选择基础单元；「今日」依次安排到期卡、单元新卡、配套阅读与听音。
3. 先回忆卡片，再查看答案并反馈。阅读/听音提交后显示解析；重新打开仍可查看结果，点击「重新练习」才开始新作答。
4. 时间有限时可跳过或延期。跳过原因、近七天反馈和作答保存在「进度」，用于真实使用后调整计划。
5. 在「卡片库」按日文、读音、中文或单元检索，筛选到期、新卡、最近困难与收藏。展开释义和收藏不会改动排程。列表每批显示 20 张，可继续加载；筛选检索会回到首批。
6. 复习每轮默认最多 10 张，可在设置中选 5 / 10 / 20 / 30 张；空格揭晓，1–4 反馈。轮次结束后可以休息或继续。
7. 设置默认每日时间；「今日」调整的时间只影响当日。任务估时超出可用时间时会提示。
8. 在「进度」回看错题；只依据每份材料最新一次实际作答，阅读辅助、合成语音与真人首遍/重练分别标明。重新答对后移出。
9. 学习页提供前台活跃计时，可手动暂停或结束；后台、失焦与闲置 60 秒后的时间不计入。「进度」显示最近七天保存的活跃时间。计时是本机记录，不上传。
10. 在「今日」或「课程」展开「本单元学习要点」，集中查看六个词句、例句、阅读重点和复盘提示。
11. 在「进度」查看「一周学习回顾」：截至昨天的七天活跃时间、学习类型、每日反馈与提交，以及任务调整原因。今日时间单列，学习安排仍由你手动调整。
12. 阅读的「阅读注音」可选关闭、材料注音、字体注音；FuriFont Serif 随应用离线提供，原材料读音优先。学习要点、卡片例句与展开后的听音文本也提供字体注音。自动读音结合上下文核对。
13. 理解题显示已答数量，可跳到首道未答题；窄窗口可在原文和理解题之间直接跳转。
14. 在「设置」定期导出 JSON。恢复先显示双方记录数量，勾选已核对后才可确认；导入前副本会保留在本机，可另行导出。
15. 阅读、听音文本、卡片例句和 JLPT 学习模式选项可切换学习层：只看原文、汉字平假名、原文下方释义/语法、罗马音或全部层。排版固定为罗马音在上、平假名在汉字上方、释义/语法在原文下方；考试模式保留原文。
16. 在任意日文材料中选中文字，会打开读音、释义和语法说明；可收藏并写笔记。笔记、收藏和 JLPT 练习进度都进入本机备份。
17. 「JLPT」按 N5–N2 与 2019–2025 建立学习索引；每个年份/等级索引包含 16 道原创分级教学题，覆盖词汇、语法、阅读、听力各 4 题，不标作历年真题。完整真题进度按 52 个实际场次/等级位置统计（2020 年只有 12 月场）。官方 2009、2012、2018 样题/练习册、题目 PDF 和听力示例提供直达入口。
18. 取得有权使用的完整真题后，先下载“当前等级字段模板”或“完整题库模板”和“52 场清单”，按 apps/nihongo-stack/src/jlpt-import.ts 中的 schema 填写，再点击「导入完整真题 JSON」一次选择多套文件，在本机按年份、场次、等级、科目和听力音频练习；切换考试模式并选择整套完整题库后，会按 N5–N2 官方建议时长倒计时。完整包还必须写明 rightsBasis，可附 rightsEvidenceUrl；导入内容随本机备份保存，不自动上传 GitHub。

## 内容范围

总计 **62 张卡、9 篇短文、10 段音频、7 个基础单元**；JLPT 教学包另行维护，目前包含 64 道分级教学题（每级 16 道，词汇/语法/阅读/听力各 4 道）和 28 个年份/等级学习索引。教学包不冒充完整考试卷；内置听力为明确标注的合成朗读练习，官方原卷听力使用官方入口或授权题库。完整历年试卷通过本机授权导入，不把未经许可的考试原文、音频或 PDF 提交到公开仓库。

- 原 v1：20 张卡、2 篇短文、3 段 Tatoeba 真人短句。ID、文字与题意保持原样。
- 新 v2：介绍自己 → 一天的时间 → 地点与交通 → 购物与数量 → 邀约与安排 → 天气与条件 → 综合复盘。
- 每单元新增六张卡、三道阅读题、两道听音题、译文、解释和复盘提示。预计 25～35 分钟，只作参考，可分多天完成。
- 新增七段音频是 **macOS Kyoko 合成语音**，用于私人基础练习，不计入真人首遍听力表现。
- 原创内容已做结构、题文对应和基础语言检查，**未经过专业日语教师审校**。七单元为连续试用材料，不是正式教材、N2 课程或分数测评。

应用内“公开资料”入口还包括 Japan Foundation 的 Irodori、Erin、Marugoto，Tadoku 分级阅读，Tatoeba 例句库，OpenJLPT（CC BY-SA 4.0）和 Bunko Commons。各来源以链接方式使用；教材和阅读材料按其网站条款，Tatoeba 文本保留 CC BY 2.0 FR 署名，OpenJLPT 保留项目及上游署名并遵守 ShareAlike，音频逐条核对，Bunko Commons 按材料页面许可使用。

应用内还随包提供一个精简的 N5–N2 离线词汇索引，来源为 Tomoshi 开放数据层的 CC BY-SA 4.0 派生数据，包含词形、平假名、中文简释和社区等级。它只用于选中解释和复盘；JLPT 等级是社区估计，不是官方词表。来源、上游署名和重建脚本见 apps/nihongo-stack/public/data/README.md 与 apps/nihongo-stack/scripts/build-openjlpt-index.py。

### 完整 JLPT 题库导入

完整试卷 JSON 的根对象保留 `schemaVersion: 1`、`id`、`year`、`session`、`level`、`title`、`sourceName`、`license`、`rightsBasis`、`rightsEvidenceUrl`、`sourceUrl`、`complete` 和 `questions`。每道题至少需要 `id`、`section`、`prompt`、`options`、`answer`；可补充 `questionNumber`、`reading`、`gloss`、`explanation`、`studySteps`、`itemType`、`audioText`、`audioUrl` 和 `sourceUrl`。根对象的 `sourceUrl` 与 `rightsEvidenceUrl` 会显示在已导入题库卡片上。

只有在确认整套试卷确实完整时才填写 `complete: true`，并同时提供：

- `session`：考试场次，例如 `07` 或 `12`；
- `rightsBasis`：说明版权所有者许可、开放许可或个人使用依据；可用 `rightsEvidenceUrl` 指向许可条款、出版社授权或来源说明；
- `questionCount`：必须等于 `questions.length`；
- `sectionQuestionCounts`：`文字・語彙`、`文法`、`読解`、`聴解` 四科的实际题数，四科实际题数和声明必须完全一致；
- 每一道题的正整数 `questionNumber`，并在各学习分区内从 1 连续编号；
- 每一道题的平假名 `reading`、中文 `gloss`、逐题 `explanation` 和至少两项 `studySteps`；
- 每一道 `聴解` 题的真实 `http(s) audioUrl`。

导入器会拒绝缺科目、低于该等级和年份格式整场题量、题号缺失、教学层不完整、题数不符、听力缺音频或没有使用依据的“完整题库”标记。可以先运行 `npm run validate:jlpt -- path/to/pack.json`，再在应用内导入。`complete: false` 适合教材节选、单科练习或只有部分题目的学习包。

官方 JLPT FAQ 与站点政策说明，官方不会公开每场考试完全相同的完整原卷；官方公开的是题型样题和练习册，练习册中的第三方材料还需要另行核对授权。因此公开仓库只保存 52 个场次/等级的覆盖清单、导入器和官方入口，不打包来源不明的原卷、答案、音频或扫描 PDF。需要“绝对完整真题”时，使用版权所有者允许你使用的本机资料导入；导入器会逐场检查题量、分区、连续题号、中文教学层和听力音频。

阅读、听音与小测草稿自动保存。听音按实际连续播放覆盖判断是否完整；拖到末尾不能绕过提交门槛。重播、拖动、变速或提前查看文本会作为辅助记录。提交后查看文本和播放不会修改已保存的证据。

## 数据与使用边界

- 使用 `com.nihongostack.desktop` 和历史 IndexedDB `nihongo-stack-codex`，旧数据可继续使用；兼容原 v1 JSON 备份。
- 桌面应用、Mac 浏览器与 iPhone 浏览器的数据彼此独立；没有自动同步或公开网站。
- 学习卡片的“进入复习”、课程的“已练”都是记录口径，不能当作掌握判定。
- 导入前副本是本机防误操作措施，不代替外部文件备份。下一次恢复会更新这份副本。
- 应用采用本机临时签名，未 Apple 公证。合成语音再分发权限未核验；公开分发前须逐项复核内容和媒体许可。

## 开发与验证

在 `apps/nihongo-stack/` 运行：

```sh
npm ci
npm run test:db
npm run test:learning
npm run test:content
npm run test:language
npm run test:jlpt
npm run build
npm run mygo:vet
npm run mygo:build
codesign --verify --deep --strict 'build/mygo/darwin-arm64/Nihongo Stack.app'
```

`test:content` 核对 v1 内容指纹、ID、引用、题目及十段音频的解码；它不是教师审校或听感审听。`test:learning` 检查播放覆盖、跳播缺口、暂停恢复、辅助证据与复习队列。`test:db` 使用内存 IndexedDB，不改真实记录。

MyGo 版的原生验收使用独立构建产物，不使用正式学习数据。MyGo 应用页面来源为 `mygo://localhost/`；浏览器前端使用 `http://127.0.0.1:5173`。当前仓库保留的旧 Tauri 验收目录和 v0.6 记录仅用于历史追溯。

窗口框架固定，只有正文滚动；短窗口侧栏可单独滚动。v0.4.0 独立 QA 与滚动证据见 `../../output/product-improvement/2026-10-08-v04/`。

本轮验收见项目根 `DELIVERY_v0.6.0_20261018.md`；审查与证据在 `../../output/product-improvement/2026-10-18-v06/`。上一版记录保留在 `DELIVERY_v0.5.0_20261018.md`。

FuriFont 来源、文件 SHA-256 与许可见 `public/fonts/README.md`；SIL OFL、MIT 和上游词典署名随包保存于 `public/licenses/`。当前字体为上游原始文件，按需载入，不向外发送学习文本。
