# Nihongo Stack 改进方案 v0.2

状态：2026-09-29 起执行。依据当前代码、项目决策和 `../../output/product-audit/2026-09-29/暂停记录.md`。这是 Nihongo Stack 当前唯一实现的改进计划。

## 产品目标与验收口径

首要任务是每天打开应用后知道该学什么、能在中断后继续、完成状态与真实记录一致，并能安全保住学习数据。界面保持现有暖白、深蓝绿与日文排版气质，但把操作放进首屏，减少标语和装饰占用。现有内容只有试用样本，页面不得暗示已形成 120 分钟完整课程或 N2 能力评估。

| 优先级 | 改进 | 验收 |
| --- | --- | --- |
| P0 | 今日计划改为可用时间与内置任务预计时间分开；一次复习不算整轮完成；基线是一次性起点，不计入每日任务 | 每日完成数只看当日任务；时间总和可追溯到具体任务；到期卡会自动更新 |
| P0 | 阅读、听力、小测中断恢复；首页推荐材料与实际进入材料一致 | 切页、关闭应用重开后答案和当前材料仍在；提交后草稿清理 |
| P0 | 听力记录播放、重听、提前看文本；未播放不允许以“首遍”提交 | 结果可区分独立首遍与辅助练习，进度页不混算 |
| P0 | 备份完整校验与导入预览；旧 v1 备份可恢复 | 坏文件不覆盖旧数据；恢复后卡片排程可继续使用；导入前可看到记录数 |
| P1 | 更紧凑的任务与练习界面、足够的文本对比度、键盘焦点和触控尺寸 | 桌面首屏可见首项行动；键盘可答题；窄屏无横向溢出 |
| P1 | 小测允许“不知道”，按错题领域给出起点建议 | 不强迫猜测；进度页显示样本及建议，不给 JLPT 分数预测 |
| P2 | 中立内容包 v2 与连续一周课程 | 每项有学习目标、先修关系、题目解释、来源/许可和语言审校记录；新包不改写 v1 ID 或语义 |
| P2 | 一周真实使用后的计划再校准 | 用任务完成、跳过原因、复习积压、阅读和听力真实作答记录调整估时与材料量 |

## 学习内容路径

先以假名音形辨认和高频词句为基础，再进入助词、活用与短句结构；随后按日常场景组织阅读和听力。每个主题至少有“识别—提取—在短文/音频中理解—复盘”四类证据。N2 题型可少量接触，用于暴露差距，不能由入门短测推断 N2 水平或通关日期。此组织方式参考[日本国际交流基金《いろどり》的 Can-do 方法](https://www.irodori.jpf.go.jp/en/about.html)，仅借鉴方法，不复制其内容。

本次实施先修 P0 与 P1。P2 需要新增可核验的原始文本、真人录音和教师审校，不能用重复试用材料填满一周。共享内容仅放版本化材料与来源，业务代码、数据库、构建配置仍留在 `apps/nihongo-stack/`。

## 连续内容的制作顺序

| 单元 | 可观察目标 | 首批材料 | 进入下一单元的证据 |
| --- | --- | --- | --- |
| 音形与读音 | 区分易混假名，读出常见词 | 假名对比卡、短词听辨 | 同一易混对在不同词里能辨认；不靠一次答对判断掌握 |
| 基础句法 | 看出主语、时间、地点和动作 | 助词与动词时态卡、两三句短文 | 能说明句子中“谁、何时、在哪里、做什么” |
| 日常任务 | 读懂安排、购物、交通等小信息 | 每个场景短文、真人短对话与理解题 | 先独立作答，再解释关键信息与错因 |
| 篇章与自然语速 | 跨句跟踪因果、转折与意图 | 较长的原创短文、许可明确的分段录音 | 阅读与首遍听力分别留证，不把查看文本后的正确率混入首遍 |
| N2 题型接触 | 识别题型要求和基础缺口 | 经许可核对的少量样题或自编同型练习 | 只记录题型表现与耗时，不换算官方分数 |

每个新单元按“目标和先修条件 → 日文原稿 → 母语者或专业教师校对 → 题目与解析反向核验 → 来源与许可登记 → 产品内试做”入库。v2 内容包须保留 v1 的 ID 和题目语义，新增独立 ID；未完成校对的材料只能标为试用内容。下一批先补基础句法与日常任务，阅读与听力保持匹配，避免只增加记忆卡。

## 分期及依赖

- **本轮，P0/P1：** 修复状态与数据口径、练习恢复、首遍听力证据、备份安全、首屏和键盘可见性；用独立测试数据核验后交付新 `.app`。
- **下一批内容，P2：** 在教师审校和录音许可核验后，提供 5～7 个连续日的完整材料。工期主要取决于内容审校与真人录音来源，不能只按写代码的时间估算。
- **一周真实使用后：** 按打开到开始的时间、完成率、跳过原因和复习积压调整每日建议。没有一周样本前，不设自动升级门槛或考试预测。
- **公开网站及同步：** 单独完成许可复审、账户与远端存储、冲突处理和本地记录迁移；不由本轮桌面打包自动触发。

## 验证

运行数据库测试、TypeScript/Vite 构建、Tauri `.app` 打包和签名检查；在独立测试环境实际走今日、阅读、听力、小测、备份流程并检查桌面与窄屏。真实学习记录不用于破坏性测试。
